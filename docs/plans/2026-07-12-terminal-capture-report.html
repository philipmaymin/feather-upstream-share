Terminal Capture:
the plan, the contract, the no-babysitting build

Any CLI agent — Claude Code, Codex, Gemini CLI — renders through a terminal framebuffer. Feather will own that framebuffer, persist it, and re-render it on the web as a faithful terminal or any way you want it. Built autonomously, verified by machines, ratified by three parties.

01What we found when we actually read the code

You asked if either of us had read feather or your home directory. We hadn't. Then we did.

The terminal already exists

server.js:2253–2326 already spawns node-pty → tmux attach per WebSocket, and the frontend renders it with ghostty-web (not xterm.js), with typing and resize working. "See + type" was an easy false win waiting to be re-claimed.

You already ran this experiment

~/cli2html + the ~/autoweb-cli2html loop: homegrown VT emulator, semantic transform, 418 keeps — then a silent crash death-spiral for 100+ iterations. The screenshot-LLM keep signal rewarded 300 trivial colorization rules over the hard TUI goal.

A real security hole

The terminal WebSocket upgrade path has no app-layer auth — it leans entirely on Authelia. Now covered by gate G7 (auth + cross-session isolation).

Tests touch your real data

Existing e2e writes into the real ~/.claude and needs a hand-started server on :4870 — both are babysitting hazards. Gate G9 makes everything hermetic: temp HOME, random port, managed boot, proven cleanup.

So the plan changed

Phase 1 is not "add a live terminal." It is: replace the ephemeral per-WebSocket attach with durable, always-on capture — an append-only event log + checkpoints + reconnect-from-seq — so nothing is ever lost, viewers can come and go (iOS Safari kills backgrounded tabs constantly), and replay is free.

02The architecture in one breath

Full detail in docs/plans/2026-07-12-003-feat-terminal-capture-plan.md

Two immutable projections of every session. The terminal (raw PTY bytes — authoritative for what you saw, input, replay) and the transcript (the agent's own .jsonl — authoritative for thinking / tool calls / text, which Feather already parses). They are never fused to manufacture semantics; they're loosely correlated, confidence-scored, and used only for navigation — click a thinking block, the terminal replay seeks to that moment.

On top: a declarative styling layer (thinking tinted, tool calls collapsed, whatever you want) over stable semantic classes, then plain ES-module renderer plugins, then optional OSC semantic marks agents could emit natively. Raw evidence stays immutable; every interpretation is derived and versioned, so better parsers can re-enrich history forever.

05The autonomy harness — you never babysit

autoweb v2, built against the exact ways autoweb v1 failed

Builders don't grade themselves

The evaluator runs as a separate OS principal — a peer container on your 10.88.0.x bridge with its own pinned, read-only copy of gates and fixtures. A builder editing package.json, fixtures, or goldens changes nothing. Keep/revert verdicts and receipts are written where builders can't forge them.

Self-healing before pinging you

5 consecutive failures → preserve evidence, auto-revert to last green, run a bounded diagnosis/replan worker, resume once. You're only notified if the recovery itself fails. No more silent 100-iteration death spirals.

Anti-accretion by tripwire

Terminal code lives in new modules behind a boundary — nothing appended to the 2.3k-line server.js. Consolidation triggers on measured duplication/complexity, not a scheduled refactor ritual. No 32k-line ui.html, ever again.

Phases end with receipts

Done = full suite ×3 in fresh hermetic environments, then a machine-readable receipt: git SHA, pinned gate-tree hash, seeds, per-gate results, artifacts. You get one digest per phase. Prose is never proof.
